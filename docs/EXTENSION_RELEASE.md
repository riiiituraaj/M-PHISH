# Extension 0.2.0 release

Distribution state: **STORE PACKAGED**, not submitted, approved or public. Run `npm ci` then `npm run package` in `extension/`. The deterministic ZIP and SHA256 file are written to `extension/release/`; the packager includes only runtime manifest, bundled scripts, HTML/CSS and icons. Never upload node_modules, test profiles, credentials or report fixtures.

For local inspection, load the `extension/` directory as an unpacked Chromium extension after building. Copy its actual extension ID into the backend EXTENSION_IDS allowlist and restart the backend. Sign in to the dashboard, request a pairing code for that ID, configure the exact backend origin in extension settings, grant the requested host permission, and exchange the code within five minutes. The bearer session expires after thirty minutes; codes cannot be reused. Cloud consent and a cloud mode must be enabled explicitly. Default local mode does not call the service.

Permissions: tabs reads URLs to bind results to the actual tab; webNavigation binds top-frame documents and SPA navigation; storage holds settings and ephemeral sessions; notifications is used only for enabled alerts; optional backend host permission allows explicitly configured service access. Top-frame content scripts on HTTP(S) pages inspect field categories and pause native sensitive submits/direct executable links. They do not read field values or inspect binary content. No remotely hosted script is loaded.

The off switch clears pending warnings/cached results, aborts requests and suppresses navigation/interaction traffic. Native actions remain paused until a trusted user continuation when evidence is unavailable or requires review. Page-script clicks cannot activate Continue once. Browser scripts can still use other data channels; injected notices can be removed/spoofed by a hostile page. This is limited intervention coverage, not universal data-loss prevention.

Validation: thirteen policy/broker tests plus eight real loaded-MV3 browser checks with a harmless controlled local API. Screenshots/results are in `extension/test-results/`. Actual production API pairing, browser-version matrix, accessibility review and store review remain required. Before submission configure owned service/support/privacy URLs, confirm disclosures match broad content-script access, supply store assets and an authorized publisher account. No invented store listing or publisher identity is supplied.
